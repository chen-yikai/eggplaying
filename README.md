# Let's Play

Expo (SDK 55) demo app. `npm start`, then press `w` for web or `a` for Android.

```
index.js                 Expo entry
src/
  App.js                 Providers, tabs and navigation
  screens/               One file per page
  games/views/           The game screens, one file per game type
  games/catalog.js       20-game catalog, built-in questions, Gemini question loaders
  components/            ui.js (UI kit and springs), Mascot, GameRow, PickerSheet
  data/                  Chat room topics
  state/                 store.js (session, saves, play history, language)
  theme/                 tokens.js (colours and type)
  lib/                   Supabase and Gemini clients
  db/schema.js           Drizzle schema, tooling only (the app must not import it)
  legacy/                Earlier screens nothing imports; kept for reference
supabase/migrations/     SQL migrations generated by Drizzle Kit
drizzle.config.js        Drizzle Kit config
.env.example             Copy to .env.local for the Gemini key and DATABASE_URL
```

## Database

Drizzle defines the schema and runs migrations. The app itself still uses `supabase-js`, because a direct Postgres connection from the client would ship the database password in the bundle.

1. In Supabase, open **Connect** and copy the **Session pooler** URI. Put it in `.env.local` as `DATABASE_URL`, with the database password URL-encoded.
2. Run `npm run db:migrate`.

To change the schema, edit `src/db/schema.js`, run `npm run db:generate`, review the new SQL, then run `npm run db:migrate`. Use `npm run db:generate -- --custom --name=<name>` for anything Drizzle can't express, such as grants and the Realtime publication.
